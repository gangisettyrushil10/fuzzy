Inside Fuzzy
01

What Fuzzy actually does

A reading workspace where you highlight text and an AI explains it in the margin — and the whole thing lives on your laptop, not in the cloud.

The 30-second pitch

Fuzzy is the "Cursor for reading." You import a PDF, you highlight a sentence that confuses you, and a little floating menu pops up with six AI buttons: Explain, Simplify, Summarize, Define, Example, Quiz me. Click one and the answer appears in a side panel — which you can save as a margin note.

📖
Why this metaphor: a margin annotator with a brain

Think of a really patient friend reading the book alongside you with a pencil. You point at a confusing line — they scribble a plain-English explanation in the margin. That's Fuzzy. Everything in this course explains how that scribbling friend actually works.

The user journey, end to end

Before we look at any code, let's trace what happens when you actually use the app. These are the five moments that matter.

1
Import a PDF

You hit "Import PDF". A native file picker opens. The file gets copied into Fuzzy's private library folder so the app owns its own copy.

2
The PDF is rendered into a real, selectable page

Each page is drawn as an image, with an invisible layer of selectable text floating on top — like a sheet of clear plastic with the words stencilled out.

3
You highlight a sentence

Your mouse drags across the text. A tiny floating toolbar with six buttons appears right where you let go.

4
You click "Explain"

The selected text plus a little surrounding context gets sent to an AI provider, which writes a plain-English explanation back.

5
You save it as a margin note

The explanation can be saved as an annotation tied to that page. It shows up in the Notes sidebar forever.

The first surprise: Fuzzy is three apps in a trench coat

Fuzzy looks like one app, but under the hood it's three separate programs that talk to each other through a tiny, locked door. This is how every Electron app works — including VS Code, Slack, and Discord.

🖼️
The Renderer (the window you see)

A web page running React. This is the entire UI — sidebars, the PDF reader, the tutor panel. Knows nothing about your computer.

🚪
The Preload (the locked door)

A tiny script that exposes a small, safe set of "buttons" the renderer can press to ask the main process to do things.

⚙️
The Main process (the back office)

A Node.js program that has full access to your laptop — files, dialogs, the SQLite database, the OpenAI API key, the works.

💡
Why split it up?

If the rendering window had direct access to your filesystem, every PDF you opened could potentially read your tax returns. The split is a security wall. We'll spend all of Module 2 on this.

Trace one click: Import PDF

Here's the actual handler that runs when you press Import. Read the code on the left, the plain English on the right.

CODE — fileService.ts:34

  const picker = parent
    ? dialog.showOpenDialog(parent, {
        title: 'Import a PDF',
        properties: ['openFile'],
        filters: [{ name: 'PDF', extensions: ['pdf'] }]
      })
    : dialog.showOpenDialog({ /* ...same options... */ })
  const { canceled, filePaths } = await picker

  return importPdfFromPath(filePaths[0])

PLAIN ENGLISH

Define a job called "openImportDialog" — it'll do work and eventually hand back either a finished import or nothing.

Pop up the native macOS file picker. Title it "Import a PDF".

Only let the user pick one file, and only show files ending in .pdf.

Wait for the user to either pick a file or hit cancel.

If they cancelled, bail out — return nothing.

Otherwise, hand the chosen file path to the next step, which copies it into Fuzzy's library and saves a row in the database.

That's the whole thing. The "magic" of importing a PDF is, on inspection, just: ask the OS for a file path, then copy bytes into a known folder. Most of Fuzzy is like this — boring plumbing, executed carefully.

02

The three rooms

Renderer, preload, main. Why every Electron app is built like a bank — with a public lobby, a teller window, and a vault in the back.

The metaphor: a bank, not a kitchen

Picture a bank branch. There are three zones with deliberate walls between them.

🛋️

The lobby (Renderer)

Anyone can walk in. Nice carpet, water cooler, the React UI. Cannot touch the cash directly.

🪟

The teller window (Preload)

A small slot with a clerk on the other side. The lobby slides paper requests through; the clerk decides what's allowed.

🔐

The vault (Main process)

Where the money lives — files, the database, your API key. No customer ever sets foot in here.

💡
Why this matters for steering AI

When you ask an AI to add a feature to an Electron app, knowing this split lets you say "put the file logic in the main process and expose it through the preload bridge" instead of vague instructions like "make it work." That's the vocabulary win.

The cast of three

🖼️
Renderer — src/renderer/

A real Chrome web page. React + TypeScript + Tailwind + Zustand for state. Has zero Node.js access — it cannot read files, run shell commands, or talk to the database.

🪟
Preload — src/preload/index.ts

Runs in a special "in-between" environment. It defines a hand-picked menu of functions that the renderer is allowed to call. Anything not on the menu, the renderer cannot do.

⚙️
Main — src/main/

A Node.js program. Owns the SQLite database, the file system, the OpenAI key, and the dialog boxes.

The teller window in code

This is the entire menu of buttons the renderer is allowed to press. Every UI interaction with the back office goes through one of these.

CODE — preload/index.ts:5 
const fuzzy: FuzzyApi = {
  documents: {
    list: () => ipcRenderer.invoke(IpcChannels.documentsList),
    import: () => ipcRenderer.invoke(IpcChannels.documentsImport),
    readFile: (id) => ipcRenderer.invoke(IpcChannels.documentsReadFile, id),
    // ...more document methods
  },
  ai: {
    runAction: (request) => ipcRenderer.invoke(IpcChannels.aiRunAction, request)
  },
  settings: {
    setOpenaiKey: (key) => ipcRenderer.invoke(IpcChannels.settingsSetOpenaiKey, key),
    // note: there is NO getOpenaiKey() — the key never leaves main
  }
}
contextBridge.exposeInMainWorld('fuzzy', fuzzy)
PLAIN ENGLISH

Build an object called "fuzzy" — this is the public menu.

Group the document-related buttons together.

"list" → ask main for all documents. "import" → ask main to open the file picker.

"readFile" → hand main a document ID and ask for the raw bytes back.

Group the AI buttons. "runAction" sends an explanation request to main.

Settings: you can set the OpenAI key. Notice — no getter. The renderer can write the key but never read it back. This is intentional.

Hand the menu through the locked door so the React UI can find it as window.fuzzy.

⚠️
The non-obvious safety move

There is no getOpenaiKey on this menu. Once written, the API key is encrypted by the OS keychain and the renderer cannot read it back. Even if a malicious PDF somehow ran code in the renderer, it could not steal your key.

The window's security settings

Down at the foundation, the main process creates the browser window with three settings that lock everything down.

Step 2 in code: catching the selection

The browser already has a built-in window.getSelection(). Fuzzy uses it directly — no fancy tracking — but adds one trick: walk up the DOM until you find the page number.

CODE — PdfReader.tsx:61 
const handleMouseUp = useCallback(() => {
  const win = window.getSelection()
  const text = win?.toString().trim() ?? ''
  if (!text || !win || win.rangeCount === 0) {
    clearSelection(); return
  }
  const range = win.getRangeAt(0)
  const node = (range.startContainer as HTMLElement | null) ?? null
  const pageEl = (node?.parentElement?.closest?.('[data-page-number]') ??
    null) as HTMLElement | null
  if (!pageEl) { clearSelection(); return }
  const pageNumber = Number(pageEl.dataset.pageNumber)
  // ...read the rect, send to selectionStore
}, [documentId, setSelection, clearSelection])
PLAIN ENGLISH

When the user lifts the mouse, run this function.

Ask the browser: "what's currently selected?" and turn it into a string.

If nothing's selected (empty string, no range), wipe any old selection and bail.

Otherwise, grab the actual selected range — the start node, end node, and pixel coordinates.

Climb up the DOM tree from the selection's start node, looking for an ancestor that has a data-page-number attribute.

If we found that ancestor, read the page number off it. Now we know which page the user selected from. Save the whole thing into the shared store so the floating menu can show up.

💡
The "data-* attribute" trick

Anywhere in HTML you can add custom attributes prefixed with data-. Fuzzy stamps each rendered page with data-page-number="3". When the selection happens, the code climbs up the tree until it finds that stamp. This is one of the most common patterns in real-world web apps.

Step 6 in code: the gatekeeper

Before main does anything with the renderer's request, it validates. Treat anything coming across the bridge as untrusted input — even though it's "your own app."

CODE — main/ipc/ai.ipc.ts:19 
function validateRequest(input: unknown): AiActionRequest {
  if (!input || typeof input !== 'object') {
    throw new Error('Invalid AI action request.')
  }
  const r = input as Partial<AiActionRequest>
  if (typeof r.selectedText !== 'string' || !r.selectedText.trim()) {
    throw new Error('selectedText is required.')
  }
  if (r.selectedText.length > 8000) {
    throw new Error('selectedText is too long (max 8000 chars).')
  }
  if (!r.action || !VALID_ACTIONS.includes(r.action)) {
    throw new Error('action must be one of: explain, simplify, ...')
  }
  return { /* sanitized request */ }
}
PLAIN ENGLISH

Take whatever the renderer sent in. Treat its type as "unknown" until proven otherwise.

First sanity check: is this even an object?

Treat the input as maybe having the right shape, then verify each field one at a time.

"selectedText" must be a non-empty string.

Cap it at 8000 characters — protects against runaway prompts that would burn tokens or cost money.

"action" must be one of the six known values. Anything else is rejected.

Only after every check passes do we hand back a clean, typed request to the AI provider.

Step 9: the AI response gets logged

Every AI response goes into a SQLite table called ai_responses. This is what lets you see "history" of explanations — and lets future Fuzzy features replay them without re-paying OpenAI.

CODE — main/ipc/ai.ipc.ts:53 
ipcMain.handle(IpcChannels.aiRunAction, async (_e, raw: unknown) => {
  const request = validateRequest(raw)
  const result = await runAiAction(request)
  insertAiResponse({
    documentId: request.documentId,
    pageNumber: request.pageNumber,
    actionType: request.action,
    inputText: request.selectedText,
    contextText: request.contextText,
    outputText: result.outputText,
    model: result.model
  })
  return result
})
PLAIN ENGLISH

When a request comes in on the "ai:runAction" channel, run this handler.

First validate the raw input (the previous slide).

Hand it to the AI provider — that returns text, model name, and which provider answered.

Save a row in the database: which document, which page, what action, what was asked, what was answered, by which model.

Hand the result back to the renderer. The UI will display it in the tutor panel.

04

Local-first by design

Your library lives in a folder you can find with Finder. Your notes live in a single file. Your API key is locked in the macOS keychain. Here's how Fuzzy enforces all of that.

The metaphor: a personal filing cabinet

Most apps today keep your data on their servers — you're renting a locker in their warehouse. Fuzzy keeps your data in a filing cabinet in your room. You own the key. You can move it. You can back it up.

🗄️
Why local-first matters for vibe coders

Local-first apps don't need server bills, user accounts, or cloud syncing infrastructure. That radically simplifies what you have to build. The trade-off: no cross-device sync. For a personal reading workspace, that's a great trade.

Where everything lives on disk

~/Library/Application Support/fuzzy/ macOS's per-app storage area — Electron's app.getPath('userData') points here
fuzzy.db The entire SQLite database — documents, notes, AI responses, settings
fuzzy.db-wal Write-ahead log — uncommitted changes buffered for speed and crash safety
library/ Imported PDFs, named by their content hash
a3f9...c2e1.pdf Each file's name IS its SHA-256 fingerprint

That's it. No login, no cloud account, no sync server. Delete that folder and Fuzzy is back to factory state.

The database setup

Three lines of pragmas turn a plain SQLite file into a fast, safe-against-crashes database.

CODE — main/services/dbService.ts:24 
db = new Database(dbPath)
db.pragma('journal_mode = WAL')
db.pragma('foreign_keys = ON')
db.pragma('synchronous = NORMAL')
db.exec(schemaSql)
PLAIN ENGLISH

Open or create the database file at the chosen path.

Switch to "WAL" mode — write-ahead logging. Faster writes, simultaneous reads, better crash recovery.

Turn on foreign keys — if you delete a document, all its pages and notes get cleaned up automatically.

Use "NORMAL" sync — a sweet spot between speed (FAST) and durability (FULL).

Run the schema file — creates all the tables if they don't exist yet.

The database tables

Seven tables, all defined in one schema file. Each one corresponds to a feature.

documents One row per imported PDF: id, title, file path, hash, page count
pages Extracted text content per page — for AI context and full-text search later
annotations Margin notes the user saved, anchored to a page
ai_responses History of every Explain/Simplify/etc. — the input, the output, the model
reading_sessions Time-budgeted plans (read these N pages in M minutes)
study_packs Generated flashcards, summary, key concepts for a document
settings Key/value blob — provider mode, model name, encrypted API key

The encrypted API key

If your Fuzzy database leaked, the API key inside it would still be useless to a thief. Here's the trick: safeStorage wraps the OS keychain.

CODE — settingsService.ts:43 
export function writeOpenaiKey(plaintextKey: string): AppSettings {
  if (!safeStorage.isEncryptionAvailable()) {
    throw new Error('Secure storage is not available...')
  }
  const trimmed = plaintextKey.trim()
  if (!trimmed) {
    throw new Error('API key cannot be empty.')
  }
  const enc = safeStorage.encryptString(trimmed)
  setSetting(KEY_OPENAI_API_KEY_ENC, enc.toString('base64'))
  return readSettings()
}
PLAIN ENGLISH

Take a plaintext OpenAI key from the user.

First check: does this OS support secure encryption? On macOS that means the Keychain is available.

Strip whitespace. Refuse if the key is empty.

Encrypt the key — the OS keychain does the work, and only this user account on this machine can decrypt it.

Save the encrypted bytes (as base64 text) into the settings table.

Even if someone copied the database file off your laptop, they couldn't read the key.

🔐
"Encryption at rest" — vocabulary win

This pattern is called encryption at rest: the data is encrypted while sitting on disk, decrypted only when actively in use. It's a phrase you'll hear constantly when reviewing security with AI or engineers — now you know what it means.

Dedupe via SHA-256: never store the same PDF twice

Imagine you import the same paper from two different folders. Fuzzy notices, doesn't waste disk space, and just opens the existing one.

CODE — fileService.ts:51 
export async function importPdfFromPath(sourcePath: string): Promise<ImportResult> {
  const dir = await ensureLibraryDir()
  const fileHash = await sha256(sourcePath)

  const existing = getDocumentByHash(fileHash)
  if (existing) {
    touchLastOpened(existing.id)
    return { document: existing, deduped: true }
  }

  const targetName = `${fileHash}.pdf`
  const targetPath = join(dir, targetName)
  await copyFile(sourcePath, targetPath)
  // ...insert row in `documents`
}
PLAIN ENGLISH

Make sure the library folder exists.

Compute the SHA-256 fingerprint of the file by hashing every byte.

Look up: have we ever imported a file with this exact fingerprint before?

If yes, just bump its "last opened" timestamp and return the existing record. We tell the caller it was deduped so the UI doesn't show "imported!" twice.

Otherwise, name the file by its hash and copy it in. Future imports of identical content will land back in the "yes, exists" branch.

05

The clever tricks

Five small engineering moves that make Fuzzy feel polished. Steal these patterns the next time you're directing AI to build something similar.

The metaphor: a magician's pockets

A stage magician's tricks aren't magic — they're a bunch of small, well-chosen techniques that together feel impossible. Same here. Each of these is a known engineering pattern; together they make Fuzzy feel solid.

🎭

Provider abstraction

The renderer doesn't know if OpenAI or a mock is answering. One interface, two implementations.

🪄

Graceful fallback

Picked OpenAI but no key configured? Silently fall back to the mock so the UI never dead-ends.

📑

Text layer trick

Render the page as an image. Float invisible selectable text on top. The browser does the highlighting for free.

📡

Single source of truth for channels

All IPC channel names live in one constants file — no string typos between sender and receiver.

📦

Structured-clone-friendly bytes

Wrap PDF buffers as Uint8Array so they survive the trip across the IPC bridge.

Trick 1: provider abstraction

Both the mock and OpenAI providers implement the same shape. The caller doesn't care which one runs.

CODE — services/ai/provider.ts:13 
export function resolveProviderMode(): AiProviderResolution {
  const settings = readSettings()
  if (settings.providerMode === 'openai') {
    const key = getDecryptedOpenaiKey()
    if (!key) return { mode: 'mock', reason: 'no_api_key' }
    return { mode: 'openai' }
  }
  return { mode: 'mock' }
}

export async function runAiAction(request: AiActionRequest): Promise<AiActionResult> {
  const resolution = resolveProviderMode()
  if (resolution.mode === 'openai') {
    return runOpenAiAction(request)
  }
  return runMockAction(request)
}
PLAIN ENGLISH

Read the user's settings.

If they want OpenAI...

...check if a key is actually configured. If not, fall back to mock with a reason ("no_api_key") so the UI can show a hint.

If yes, OpenAI it is.

Otherwise, mock by default.

The runAiAction function picks one branch and calls it. From the caller's perspective, both functions return the same shape — output text, model name, provider. No special-casing in the UI.

💡
"Strategy pattern" — vocabulary win

Engineers call this the strategy pattern: pluggable implementations behind one interface. The next time you're talking to AI, you can say "use the strategy pattern to swap between Anthropic and OpenAI" and they'll know exactly what you mean.

Trick 3: the invisible text layer

This is the cleverest UI move in Fuzzy. PDFs are rendered as bitmaps — pixels — but the user expects to select text. How?

CODE — components/pdf/PdfPage.tsx:71 
const textContent = await page.getTextContent()

textLayer = new TextLayer({
  textContentSource: textContent,
  container: textDiv,
  viewport
})
await textLayer.render()
PLAIN ENGLISH

Ask pdf.js for the text content of this page — every word with its on-page coordinates.

Build a TextLayer: a transparent <div> overlaying the canvas, with a <span> for every text run, positioned exactly where the printed pixels are.

Render. The user sees the bitmap. They drag to select. Their mouse is actually selecting the invisible spans, but the browser's native text selection works exactly as expected.

📑
Why not just render text?

Fonts in PDFs are often weird, unembedded, or rely on layout the browser can't replicate. Rendering as a bitmap guarantees pixel-perfect fidelity. Layering invisible text on top gets you both — accurate visuals AND selectable text.

Trick 4: one source of truth for channel names

Sender and receiver agree on a channel name. If they disagree by even one character, messages disappear silently. So both sides import from the same constants file.

CODE — shared/ipc/channels.ts:4 
export const IpcChannels = {
  healthPing: 'health:ping',

  documentsList: 'documents:list',
  documentsImport: 'documents:import',
  documentsReadFile: 'documents:readFile',
  // ...one entry per channel, both ends import from this file

  aiRunAction: 'ai:runAction',
  settingsSetOpenaiKey: 'settings:setOpenaiKey'
} as const
PLAIN ENGLISH

Define one big constants object listing every IPC channel name.

Each channel is a colon-separated string like "documents:import" — colon-style is just a convention, like a postal address.

Both the preload (sender) and main (receiver) import from this file. If you misspell aiRunAction, TypeScript yells at compile time. If you misspelled it as a raw string in two places, it would silently fail at runtime.

"as const" tells TypeScript: don't widen these to plain strings. Treat each one as its own exact type. This catches subtle bugs.

Trick 5: surviving the bridge with Uint8Array

Sending a PDF's bytes from main back to the renderer sounds simple. It isn't. IPC serializes objects using a thing called structured clone, and not every type survives.

CODE — fileService.ts:78 
export async function readDocumentBytes(filePath: string): Promise<Uint8Array> {
  const buf = await readFile(filePath)
  // Wrap as a plain Uint8Array so it survives the structured-clone IPC.
  return new Uint8Array(buf.buffer, buf.byteOffset, buf.byteLength)
}
PLAIN ENGLISH

Read the PDF file from disk into memory. Node hands back a "Buffer" — its own special bytes-container.

The comment explains the gotcha: Buffer is Node-specific. When IPC serializes it, weird stuff can happen.

Wrap it in a plain Uint8Array (a standard typed array). Same bytes underneath, but a type that structured clone handles cleanly. The renderer receives clean bytes that pdf.js can parse.

⚠️
A real bug that AI would miss

If you asked an AI to "read the PDF and send it to the renderer," it would probably hand back the raw Node Buffer. It would look right in tests, then mysteriously corrupt in production. The one-line wrap is the kind of detail that comes from experience — exactly the kind of intervention you want to be able to make.

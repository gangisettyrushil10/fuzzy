The clever tricks

Five small engineering moves that make Fuzzy feel polished. Steal these patterns the next time you're directing AI to build something similar.

The metaphor: a magician's pockets

A stage magician's tricks aren't magic — they're a bunch of small, well-chosen techniques that together feel impossible. Same here. Each of these is a known engineering pattern; together they make Fuzzy feel solid.

🎭

Provider abstraction

The renderer doesn't know if OpenAI or a mock is answering. One interface, two implementations.

🪄

Graceful fallback

Picked OpenAI but no key configured? Silently fall back to the mock so the UI never dead-ends.

📑

Text layer trick

Render the page as an image. Float invisible selectable text on top. The browser does the highlighting for free.

📡

Single source of truth for channels

All IPC channel names live in one constants file — no string typos between sender and receiver.

📦

Structured-clone-friendly bytes

Wrap PDF buffers as Uint8Array so they survive the trip across the IPC bridge.

Trick 1: provider abstraction

Both the mock and OpenAI providers implement the same shape. The caller doesn't care which one runs.

CODE — services/ai/provider.ts:13 
export function resolveProviderMode(): AiProviderResolution {
  const settings = readSettings()
  if (settings.providerMode === 'openai') {
    const key = getDecryptedOpenaiKey()
    if (!key) return { mode: 'mock', reason: 'no_api_key' }
    return { mode: 'openai' }
  }
  return { mode: 'mock' }
}

export async function runAiAction(request: AiActionRequest): Promise<AiActionResult> {
  const resolution = resolveProviderMode()
  if (resolution.mode === 'openai') {
    return runOpenAiAction(request)
  }
  return runMockAction(request)
}
PLAIN ENGLISH

Read the user's settings.

If they want OpenAI...

...check if a key is actually configured. If not, fall back to mock with a reason ("no_api_key") so the UI can show a hint.

If yes, OpenAI it is.

Otherwise, mock by default.

The runAiAction function picks one branch and calls it. From the caller's perspective, both functions return the same shape — output text, model name, provider. No special-casing in the UI.

💡
"Strategy pattern" — vocabulary win

Engineers call this the strategy pattern: pluggable implementations behind one interface. The next time you're talking to AI, you can say "use the strategy pattern to swap between Anthropic and OpenAI" and they'll know exactly what you mean.

Trick 3: the invisible text layer

This is the cleverest UI move in Fuzzy. PDFs are rendered as bitmaps — pixels — but the user expects to select text. How?

CODE — components/pdf/PdfPage.tsx:71 
const textContent = await page.getTextContent()

textLayer = new TextLayer({
  textContentSource: textContent,
  container: textDiv,
  viewport
})
await textLayer.render()
PLAIN ENGLISH

Ask pdf.js for the text content of this page — every word with its on-page coordinates.

Build a TextLayer: a transparent <div> overlaying the canvas, with a <span> for every text run, positioned exactly where the printed pixels are.

Render. The user sees the bitmap. They drag to select. Their mouse is actually selecting the invisible spans, but the browser's native text selection works exactly as expected.

📑
Why not just render text?

Fonts in PDFs are often weird, unembedded, or rely on layout the browser can't replicate. Rendering as a bitmap guarantees pixel-perfect fidelity. Layering invisible text on top gets you both — accurate visuals AND selectable text.

Trick 4: one source of truth for channel names

Sender and receiver agree on a channel name. If they disagree by even one character, messages disappear silently. So both sides import from the same constants file.

CODE — shared/ipc/channels.ts:4 
export const IpcChannels = {
  healthPing: 'health:ping',

  documentsList: 'documents:list',
  documentsImport: 'documents:import',
  documentsReadFile: 'documents:readFile',
  // ...one entry per channel, both ends import from this file

  aiRunAction: 'ai:runAction',
  settingsSetOpenaiKey: 'settings:setOpenaiKey'
} as const
PLAIN ENGLISH

Define one big constants object listing every IPC channel name.

Each channel is a colon-separated string like "documents:import" — colon-style is just a convention, like a postal address.

Both the preload (sender) and main (receiver) import from this file. If you misspell aiRunAction, TypeScript yells at compile time. If you misspelled it as a raw string in two places, it would silently fail at runtime.

"as const" tells TypeScript: don't widen these to plain strings. Treat each one as its own exact type. This catches subtle bugs.

Trick 5: surviving the bridge with Uint8Array

Sending a PDF's bytes from main back to the renderer sounds simple. It isn't. IPC serializes objects using a thing called structured clone, and not every type survives.

CODE — fileService.ts:78 
export async function readDocumentBytes(filePath: string): Promise<Uint8Array> {
  const buf = await readFile(filePath)
  // Wrap as a plain Uint8Array so it survives the structured-clone IPC.
  return new Uint8Array(buf.buffer, buf.byteOffset, buf.byteLength)
}
PLAIN ENGLISH

Read the PDF file from disk into memory. Node hands back a "Buffer" — its own special bytes-container.

The comment explains the gotcha: Buffer is Node-specific. When IPC serializes it, weird stuff can happen.

Wrap it in a plain Uint8Array (a standard typed array). Same bytes underneath, but a type that structured clone handles cleanly. The renderer receives clean bytes that pdf.js can parse.

⚠️
A real bug that AI would miss

If you asked an AI to "read the PDF and send it to the renderer," it would probably hand back the raw Node Buffer. It would look right in tests, then mysteriously corrupt in production. The one-line wrap is the kind of detail that comes from experience — exactly the kind of intervention you want to be able to make.

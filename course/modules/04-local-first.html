Local-first by design

Your library lives in a folder you can find with Finder. Your notes live in a single file. Your API key is locked in the macOS keychain. Here's how Fuzzy enforces all of that.

The metaphor: a personal filing cabinet

Most apps today keep your data on their servers — you're renting a locker in their warehouse. Fuzzy keeps your data in a filing cabinet in your room. You own the key. You can move it. You can back it up.

🗄️
Why local-first matters for vibe coders

Local-first apps don't need server bills, user accounts, or cloud syncing infrastructure. That radically simplifies what you have to build. The trade-off: no cross-device sync. For a personal reading workspace, that's a great trade.

Where everything lives on disk

~/Library/Application Support/fuzzy/ macOS's per-app storage area — Electron's app.getPath('userData') points here
fuzzy.db The entire SQLite database — documents, notes, AI responses, settings
fuzzy.db-wal Write-ahead log — uncommitted changes buffered for speed and crash safety
library/ Imported PDFs, named by their content hash
a3f9...c2e1.pdf Each file's name IS its SHA-256 fingerprint

That's it. No login, no cloud account, no sync server. Delete that folder and Fuzzy is back to factory state.

The database setup

Three lines of pragmas turn a plain SQLite file into a fast, safe-against-crashes database.

CODE — main/services/dbService.ts:24 
db = new Database(dbPath)
db.pragma('journal_mode = WAL')
db.pragma('foreign_keys = ON')
db.pragma('synchronous = NORMAL')
db.exec(schemaSql)
PLAIN ENGLISH

Open or create the database file at the chosen path.

Switch to "WAL" mode — write-ahead logging. Faster writes, simultaneous reads, better crash recovery.

Turn on foreign keys — if you delete a document, all its pages and notes get cleaned up automatically.

Use "NORMAL" sync — a sweet spot between speed (FAST) and durability (FULL).

Run the schema file — creates all the tables if they don't exist yet.

The database tables

Seven tables, all defined in one schema file. Each one corresponds to a feature.

documents One row per imported PDF: id, title, file path, hash, page count
pages Extracted text content per page — for AI context and full-text search later
annotations Margin notes the user saved, anchored to a page
ai_responses History of every Explain/Simplify/etc. — the input, the output, the model
reading_sessions Time-budgeted plans (read these N pages in M minutes)
study_packs Generated flashcards, summary, key concepts for a document
settings Key/value blob — provider mode, model name, encrypted API key

The encrypted API key

If your Fuzzy database leaked, the API key inside it would still be useless to a thief. Here's the trick: safeStorage wraps the OS keychain.

CODE — settingsService.ts:43 
export function writeOpenaiKey(plaintextKey: string): AppSettings {
  if (!safeStorage.isEncryptionAvailable()) {
    throw new Error('Secure storage is not available...')
  }
  const trimmed = plaintextKey.trim()
  if (!trimmed) {
    throw new Error('API key cannot be empty.')
  }
  const enc = safeStorage.encryptString(trimmed)
  setSetting(KEY_OPENAI_API_KEY_ENC, enc.toString('base64'))
  return readSettings()
}
PLAIN ENGLISH

Take a plaintext OpenAI key from the user.

First check: does this OS support secure encryption? On macOS that means the Keychain is available.

Strip whitespace. Refuse if the key is empty.

Encrypt the key — the OS keychain does the work, and only this user account on this machine can decrypt it.

Save the encrypted bytes (as base64 text) into the settings table.

Even if someone copied the database file off your laptop, they couldn't read the key.

🔐
"Encryption at rest" — vocabulary win

This pattern is called encryption at rest: the data is encrypted while sitting on disk, decrypted only when actively in use. It's a phrase you'll hear constantly when reviewing security with AI or engineers — now you know what it means.

Dedupe via SHA-256: never store the same PDF twice

Imagine you import the same paper from two different folders. Fuzzy notices, doesn't waste disk space, and just opens the existing one.

CODE — fileService.ts:51 
export async function importPdfFromPath(sourcePath: string): Promise<ImportResult> {
  const dir = await ensureLibraryDir()
  const fileHash = await sha256(sourcePath)

  const existing = getDocumentByHash(fileHash)
  if (existing) {
    touchLastOpened(existing.id)
    return { document: existing, deduped: true }
  }

  const targetName = `${fileHash}.pdf`
  const targetPath = join(dir, targetName)
  await copyFile(sourcePath, targetPath)
  // ...insert row in `documents`
}
PLAIN ENGLISH

Make sure the library folder exists.

Compute the SHA-256 fingerprint of the file by hashing every byte.

Look up: have we ever imported a file with this exact fingerprint before?

If yes, just bump its "last opened" timestamp and return the existing record. We tell the caller it was deduped so the UI doesn't show "imported!" twice.

Otherwise, name the file by its hash and copy it in. Future imports of identical content will land back in the "yes, exists" branch.

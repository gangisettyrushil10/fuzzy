The magic loop

Highlight a sentence. An explanation appears. Trace the journey of those words from your cursor to OpenAI and back.

The metaphor: a relay race

Five runners stand on a track, each holding a baton-shaped piece of data. The selected text is the baton. Each runner does one focused job and hands off to the next.

🏃
Why a relay, not a phone call

If one runner tried to do everything — read the selection, encrypt the API key, call OpenAI, save to the DB, update the UI — the code would be a tangle. By splitting the work into a chain of focused steps, each piece stays small enough to reason about.

Step 2 in code: catching the selection

The browser already has a built-in window.getSelection(). Fuzzy uses it directly — no fancy tracking — but adds one trick: walk up the DOM until you find the page number.

CODE — PdfReader.tsx:61 
const handleMouseUp = useCallback(() => {
  const win = window.getSelection()
  const text = win?.toString().trim() ?? ''
  if (!text || !win || win.rangeCount === 0) {
    clearSelection(); return
  }
  const range = win.getRangeAt(0)
  const node = (range.startContainer as HTMLElement | null) ?? null
  const pageEl = (node?.parentElement?.closest?.('[data-page-number]') ??
    null) as HTMLElement | null
  if (!pageEl) { clearSelection(); return }
  const pageNumber = Number(pageEl.dataset.pageNumber)
  // ...read the rect, send to selectionStore
}, [documentId, setSelection, clearSelection])
PLAIN ENGLISH

When the user lifts the mouse, run this function.

Ask the browser: "what's currently selected?" and turn it into a string.

If nothing's selected (empty string, no range), wipe any old selection and bail.

Otherwise, grab the actual selected range — the start node, end node, and pixel coordinates.

Climb up the DOM tree from the selection's start node, looking for an ancestor that has a data-page-number attribute.

If we found that ancestor, read the page number off it. Now we know which page the user selected from. Save the whole thing into the shared store so the floating menu can show up.

💡
The "data-* attribute" trick

Anywhere in HTML you can add custom attributes prefixed with data-. Fuzzy stamps each rendered page with data-page-number="3". When the selection happens, the code climbs up the tree until it finds that stamp. This is one of the most common patterns in real-world web apps.

Step 6 in code: the gatekeeper

Before main does anything with the renderer's request, it validates. Treat anything coming across the bridge as untrusted input — even though it's "your own app."

CODE — main/ipc/ai.ipc.ts:19 
function validateRequest(input: unknown): AiActionRequest {
  if (!input || typeof input !== 'object') {
    throw new Error('Invalid AI action request.')
  }
  const r = input as Partial<AiActionRequest>
  if (typeof r.selectedText !== 'string' || !r.selectedText.trim()) {
    throw new Error('selectedText is required.')
  }
  if (r.selectedText.length > 8000) {
    throw new Error('selectedText is too long (max 8000 chars).')
  }
  if (!r.action || !VALID_ACTIONS.includes(r.action)) {
    throw new Error('action must be one of: explain, simplify, ...')
  }
  return { /* sanitized request */ }
}
PLAIN ENGLISH

Take whatever the renderer sent in. Treat its type as "unknown" until proven otherwise.

First sanity check: is this even an object?

Treat the input as maybe having the right shape, then verify each field one at a time.

"selectedText" must be a non-empty string.

Cap it at 8000 characters — protects against runaway prompts that would burn tokens or cost money.

"action" must be one of the six known values. Anything else is rejected.

Only after every check passes do we hand back a clean, typed request to the AI provider.

Step 9: the AI response gets logged

Every AI response goes into a SQLite table called ai_responses. This is what lets you see "history" of explanations — and lets future Fuzzy features replay them without re-paying OpenAI.

CODE — main/ipc/ai.ipc.ts:53 
ipcMain.handle(IpcChannels.aiRunAction, async (_e, raw: unknown) => {
  const request = validateRequest(raw)
  const result = await runAiAction(request)
  insertAiResponse({
    documentId: request.documentId,
    pageNumber: request.pageNumber,
    actionType: request.action,
    inputText: request.selectedText,
    contextText: request.contextText,
    outputText: result.outputText,
    model: result.model
  })
  return result
})
PLAIN ENGLISH

When a request comes in on the "ai:runAction" channel, run this handler.

First validate the raw input (the previous slide).

Hand it to the AI provider — that returns text, model name, and which provider answered.

Save a row in the database: which document, which page, what action, what was asked, what was answered, by which model.

Hand the result back to the renderer. The UI will display it in the tutor panel.

The three rooms

Renderer, preload, main. Why every Electron app is built like a bank — with a public lobby, a teller window, and a vault in the back.

The metaphor: a bank, not a kitchen

Picture a bank branch. There are three zones with deliberate walls between them.

🛋️

The lobby (Renderer)

Anyone can walk in. Nice carpet, water cooler, the React UI. Cannot touch the cash directly.

🪟

The teller window (Preload)

A small slot with a clerk on the other side. The lobby slides paper requests through; the clerk decides what's allowed.

🔐

The vault (Main process)

Where the money lives — files, the database, your API key. No customer ever sets foot in here.

💡
Why this matters for steering AI

When you ask an AI to add a feature to an Electron app, knowing this split lets you say "put the file logic in the main process and expose it through the preload bridge" instead of vague instructions like "make it work." That's the vocabulary win.

The cast of three

🖼️
Renderer — src/renderer/

A real Chrome web page. React + TypeScript + Tailwind + Zustand for state. Has zero Node.js access — it cannot read files, run shell commands, or talk to the database.

🪟
Preload — src/preload/index.ts

Runs in a special "in-between" environment. It defines a hand-picked menu of functions that the renderer is allowed to call. Anything not on the menu, the renderer cannot do.

⚙️
Main — src/main/

A Node.js program. Owns the SQLite database, the file system, the OpenAI key, and the dialog boxes.

The teller window in code

This is the entire menu of buttons the renderer is allowed to press. Every UI interaction with the back office goes through one of these.

CODE — preload/index.ts:5 
const fuzzy: FuzzyApi = {
  documents: {
    list: () => ipcRenderer.invoke(IpcChannels.documentsList),
    import: () => ipcRenderer.invoke(IpcChannels.documentsImport),
    readFile: (id) => ipcRenderer.invoke(IpcChannels.documentsReadFile, id),
    // ...more document methods
  },
  ai: {
    runAction: (request) => ipcRenderer.invoke(IpcChannels.aiRunAction, request)
  },
  settings: {
    setOpenaiKey: (key) => ipcRenderer.invoke(IpcChannels.settingsSetOpenaiKey, key),
    // note: there is NO getOpenaiKey() — the key never leaves main
  }
}
contextBridge.exposeInMainWorld('fuzzy', fuzzy)
PLAIN ENGLISH

Build an object called "fuzzy" — this is the public menu.

Group the document-related buttons together.

"list" → ask main for all documents. "import" → ask main to open the file picker.

"readFile" → hand main a document ID and ask for the raw bytes back.

Group the AI buttons. "runAction" sends an explanation request to main.

Settings: you can set the OpenAI key. Notice — no getter. The renderer can write the key but never read it back. This is intentional.

Hand the menu through the locked door so the React UI can find it as window.fuzzy.

⚠️
The non-obvious safety move

There is no getOpenaiKey on this menu. Once written, the API key is encrypted by the OS keychain and the renderer cannot read it back. Even if a malicious PDF somehow ran code in the renderer, it could not steal your key.

The window's security settings

Down at the foundation, the main process creates the browser window with three settings that lock everything down.

CODE — main/index.ts:8 
const mainWindow = new BrowserWindow({
  width: 1440,
  height: 900,
  webPreferences: {
    preload: join(__dirname, '../preload/index.js'),
    sandbox: false,
    contextIsolation: true
  }
})
PLAIN ENGLISH

Make a new browser window — 1440 by 900 pixels.

Fancy settings live under webPreferences.

"preload" → load this script first, before the page. This is the teller window.

"contextIsolation: true" → keep the page's JavaScript world walled off from the preload's world. They share nothing except the menu we explicitly handed over.

Without that flag, malicious scripts on the page could reach into the preload and grab the keys to the kingdom.

A conversation between the three rooms

Here's what actually happens when you click "Import PDF". Watch them talk to each other — one message at a time.

UI
Renderer (React UI)

User just clicked "Import PDF". I have no way to open a file picker myself. Hey teller — could you forward this?

PL
Preload (the bridge)

Sure. I see "documents.import()" on my menu. Forwarding to the channel "documents:import" in main.

M
Main (the back office)

Got it. Opening the native macOS file picker now... user picked "paper.pdf". I'll copy it to the library folder, hash it for dedupe, and write a row in SQLite.

M
Main (the back office)

Done. Here's the new document record: { id, title, filePath, ... }. Sending it back through the bridge.

UI
Renderer (React UI)

Got the new document! Adding it to the sidebar list and opening it in the reader. The user sees their PDF appear.
